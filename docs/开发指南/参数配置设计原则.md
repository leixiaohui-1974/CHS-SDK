# 参数配置设计原则

## 🎯 **设计目标**

建立清晰的参数分类和配置原则，避免不合理的硬编码，提高系统的可配置性和可维护性。

## 📋 **参数分类**

### **1. 物理常数（Physical Constants）**
**定义**: 不可变的自然物理常数
**位置**: 在类的 `__init__` 方法中定义
**命名**: 全大写，以 `_` 分隔

```python
# ✅ 正确 - 真正的物理常数
self.GRAVITY_ACCELERATION = 9.81      # 重力加速度 (m/s²)
self.WATER_DENSITY = 1000            # 水密度 (kg/m³)
self.WEIR_FLOW_EXPONENT = 0.5         # 堰流公式指数
```

### **2. 系统框架常数（Framework Constants）**
**定义**: 与仿真框架机制相关的常数
**位置**: 在类的 `__init__` 方法中定义
**命名**: 全大写，前缀 `DEFAULT_`

```python
# ✅ 正确 - 框架机制常数
self.DEFAULT_TIME_STEP = 1.0          # 默认仿真时间步长
self.DEFAULT_PRINT_INTERVAL = 10      # 默认打印间隔
self.MIN_OPENING_LIMIT = 0.0          # 物理最小开度限制
self.MAX_OPENING_LIMIT = 1.0          # 物理最大开度限制
```

### **3. 用户配置参数（User Configuration）**
**定义**: 必须或应该由用户提供的参数
**位置**: 从 `config` 或 `parameters` 获取
**验证**: 必需参数要进行存在性检查

```python
# ✅ 正确 - 用户必须提供的参数
physical_config = config.get('physical_system', {})
if not physical_config:
    raise ValueError("物理系统配置 'physical_system' 是必需的")

self.channel_surface_area = physical_config['channel_surface_area']  # 必需

# ✅ 正确 - 可选参数有默认值
sensor_config = config.get('sensors', {})
self.noise_level = sensor_config.get('noise_level', self.DEFAULT_NOISE_LEVEL)
```

### **4. 初始状态（Initial State）**
**定义**: 系统的初始运行状态
**位置**: 从 `initial_state` 获取
**验证**: 关键状态要进行存在性检查

```python
# ✅ 正确 - 关键初始状态必须提供
if 'upstream_level' not in initial_state:
    raise ValueError("初始上游水位 'upstream_level' 是必需的")
    
self.upstream_level = initial_state['upstream_level']

# ✅ 正确 - 非关键状态可有默认值
self.gate_opening = initial_state.get('gate_opening', 0.0)  # 默认关闭
```

## ❌ **不合理的硬编码示例**

### **业务参数硬编码**
```python
# ❌ 错误 - 设备特性不应硬编码
self.DEFAULT_MAX_FLOW_RATE = 10.0    # 应该由用户配置
self.DEFAULT_CHANNEL_SURFACE_AREA = 10000  # 应该由用户配置
self.DEFAULT_GATE_FLOW_COEFFICIENT = 20    # 应该由用户配置
```

### **初始状态硬编码**
```python
# ❌ 错误 - 初始状态不应硬编码
self.DEFAULT_UPSTREAM_LEVEL = 5.0     # 应该由用户提供
self.gate_opening = 0.5               # 应该由用户配置
```

### **业务逻辑硬编码**
```python
# ❌ 错误 - 扰动参数不应硬编码
self.DISTURBANCE_START_STEP = 50      # 应该由用户配置
self.DISTURBANCE_INFLOW = 5           # 应该由用户配置
```

## ✅ **正确的设计模式**

### **配置驱动的设计**
```python
class OntologySimulationAgent(Agent):
    def __init__(self, agent_id: str, message_bus: MessageBus, config: dict = None, **kwargs):
        # 1. 物理常数
        self.GRAVITY_ACCELERATION = 9.81
        
        # 2. 框架常数
        self.DEFAULT_NOISE_LEVEL = 0.01
        
        # 3. 验证必需配置
        physical_config = config.get('physical_system', {})
        if not physical_config:
            raise ValueError("物理系统配置是必需的")
        
        # 4. 从配置获取参数
        self.channel_surface_area = physical_config['channel_surface_area']
        self.max_gate_speed = config['gate_parameters']['max_speed']
        
        # 5. 验证初始状态
        initial_state = config.get('initial_state', {})
        if 'upstream_level' not in initial_state:
            raise ValueError("初始上游水位是必需的")
        
        self.upstream_level = initial_state['upstream_level']
```

### **参数验证策略**
```python
# ✅ 必需参数验证
def _validate_required_params(self, params: dict, required_keys: list):
    """验证必需参数"""
    missing = [key for key in required_keys if key not in params]
    if missing:
        raise ValueError(f"缺少必需参数: {missing}")

# ✅ 参数范围验证
def _validate_param_range(self, value: float, min_val: float, max_val: float, name: str):
    """验证参数范围"""
    if not (min_val <= value <= max_val):
        raise ValueError(f"参数 '{name}' 值 {value} 超出范围 [{min_val}, {max_val}]")
```

## 📝 **配置文件结构**

### **推荐的配置结构**
```yaml
# 初始状态（必需）
initial_state:
  upstream_level: 5.2
  downstream_level: 4.3
  inflow: 12.5

# 物理系统参数（必需）
physical_system:
  channel_surface_area: 8500

# 设备参数（必需）
gate_parameters:
  max_speed: 0.08
  flow_coefficient: 25

# 仿真配置（可选）
simulation:
  time_step: 1.0
  print_interval: 5

# 扰动配置（可选）
disturbances:
  enabled: true
  start_step: 60
  end_step: 120
  inflow_value: 8.0
```

## 🔍 **代码审查检查点**

### **检查清单**
1. **物理常数检查**: 是否只包含真正的物理常数？
2. **必需参数检查**: 是否验证了所有必需参数的存在性？
3. **默认值合理性**: 默认值是否合理且有文档说明？
4. **配置完整性**: 是否提供了完整的配置示例？
5. **错误处理**: 是否有清晰的错误信息？

### **重构指导**
1. **识别硬编码**: 找出所有硬编码的业务参数
2. **分类参数**: 区分物理常数、框架常数、用户配置
3. **设计配置结构**: 创建层次化的配置结构
4. **添加验证**: 添加参数验证和错误处理
5. **提供示例**: 创建完整的配置示例文件

## 🎯 **设计收益**

- **可配置性**: 用户可以根据实际情况配置参数
- **可重用性**: 同一个类可以用于不同的场景
- **可维护性**: 参数集中管理，易于修改
- **可测试性**: 可以通过不同配置测试不同场景
- **文档化**: 配置文件本身就是最好的文档
