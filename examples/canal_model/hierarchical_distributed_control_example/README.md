# 分层分布式控制示例概述

## 问题描述
本示例构建了一个包含两段渠道与多座闸门的输水系统，需要在多变的下游需水条件下保持各控制断面的水位稳定。系统引入突发的取水扰动与设定点变化，如果仅依靠单一控制回路容易出现滞后和大幅超调，因此需要分层分布式的协同调度策略。

## 建模原理
- **物理建模**：采用统一的渠道与闸门组件，基于质量守恒与达西-韦斯巴赫水头损失关系计算水位与流量演化。
- **分层结构**：上层的 `CentralMPCAgent` 每 300 秒评估全局水位偏差并下发新的目标水位；下层的 `StructuredControlAgent` 以 PID 控制实时调节各闸门开度，实现对动态设定点的快速跟踪。
- **消息驱动**：所有感知数据、指令与执行动作均通过 `MessageBus` 以主题发布/订阅方式传递，保证各智能体解耦且易于扩展。

## 计算结果
- 仿真时长 3600 s，时间步长 1 s。
- 自动性能评估显示：时间步数 3601，校验变量 6 项，质量守恒最大相对误差 0.00%，合理性评分 1.000。
- 控制效果：上下游渠道水位在扰动发生后于约 5 分钟内回到目标范围，闸门开度调节平稳无明显超调。

## 讨论
分层方案能够在不增加本地控制复杂度的情况下引入全局优化信息，显著降低扰动后的恢复时间。消息驱动的通信方式方便注入更多感知源或冗余控制器，日志中也可清晰追踪各层级决策。

## 建议
1. 可进一步将 MPC 预测模型参数化为可在线辨识的形式，以适应季节性水力特性变化。
2. 建议在运行前配置 `reports/` 目录的可视化脚本，将设定点与水位跟踪误差绘制成图，便于对控制性能进行回顾分析。
3. 若要部署到真实渠道，可增加网络时延扰动模块，验证通信延迟对分层结构的影响。
