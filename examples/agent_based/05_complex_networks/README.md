# 分支河网多水库协同控制示例

本示例展示如何在 CHS-SDK 中利用图结构仿真与多智能体协同控制同时调节两座水库。新版情景通过统一的物理参数与控制器标定，使四种运行方式均能在 2400 s 内将水位稳定在目标附近，并获得满分的性能评分。

## 问题描述

- **目标**：将上游水库 `res1` 的水位从 9.2 m 下调至 8.0 m，将主河道旁水库 `res2` 从 14.5 m 调整到 12.8 m。
- **挑战**：
  1. 分支河道与主河道在闸门节点汇合，必须保证拓扑无环且保持水量守恒。
  2. 闸门开度需要兼顾快速泄洪与执行器速率约束，避免振荡或过度削减。
  3. 不同运行框架（脚本、YAML、统一运行器、通用运行器）需要共用一套组件与消息主题，保证结果一致。
- **解决思路**：
  - 将水系统表示为有向图，在 `SimulationHarness` 中统一管理组件与连接顺序。
  - 为两座水库标定较小的表面积与恒定入流（5 m³/s 与 8 m³/s），配合闸门最大开度变化率（0.25 与 0.22 s⁻¹）以兼顾响应速度与稳定性。
  - 利用 `LocalControlAgent` 封装 PID 控制器，统一解析观测与动作主题；`CentralDispatcherAgent` 则在水位过高时微调设定值，以平滑过渡。

## 建模与情景分析方法

1. **物理模型**：
   - 水库：基于库容曲线 `storage_curve` 计算水位-体积关系，并叠加恒定入流模拟来水补给。
   - 闸门：使用孔口出流公式，结合最大开度变化率限制，实现开度目标的渐进跟踪。
   - 河道：采用线性蓄泄模型，分支河道与主河道按 `k` 系数设置汇流速度。
2. **通信拓扑**：
   - 图结构连接为 `res1 → g1 → trib_chan → main_chan → g3` 与 `res2 → g2 → main_chan`。
   - 数字孪生负责向 `state.*` 主题发布状态，控制器订阅水位并向 `action.*` 主题发布开度指令。
3. **控制策略**：
   - `res1` PID 参数 `(-0.6, -0.07, -0.12)`，目标 8.0 m；`res2` PID 参数 `(-0.55, -0.06, -0.11)`，目标 12.8 m。
   - 调度器在水位 7.8–8.6 m 区间内切换设定值 8.1/7.9 m，防止超调。
4. **仿真设置**：总时长 2400 s，步长 1 s，所有运行方式共用相同配置文件或构建逻辑。

## 四种运行方式

| 方式 | 命令 | 说明 |
| --- | --- | --- |
| 1. 硬编码脚本 | `python run_branched_network_simulation.py` | 直接使用 `SimulationHarness` 手工装配组件、连接和智能体。 |
| 2. Builder 脚本 | `python run_branched_network_simulation_refactored.py` | 借助 `SimulationBuilder` 批量创建水库、闸门与河道，复用统一参数。 |
| 3. YAML 配置驱动 | `python run_config.py` | 从 `config.yml` 读取组件、网络、智能体与验证规则，运行后生成 `complex_networks_report.md` 报告。 |
| 4. 统一/通用运行器 | `python ../run_unified_scenario.py --example agent_based_05_complex_networks`<br>`python ../run_universal_config.py --example agent_based_05_complex_networks` | 通过统一入口加载 `unified_config.yml` 或 `universal_config.yml`，便于批量测试与平台集成。 |

四种方式共用相同的物理参数和消息主题，结果一致，可互相作为回归测试基准。

## 结果分析

`run_config.py` 自动生成的报告显示：

- `res1` 最终水位 8.10 m，绝对误差 0.10 m，约在 1860 s 时进入容差带；
- `res2` 最终水位 12.81 m，绝对误差 0.01 m，约在 1720 s 时达到稳态；
- 闸门 `g1` 开度在 0.000–1.000 之间调节，`g2` 在 0.000–0.835 之间调节，最终分别收敛到 0.00076 与 0.055；
- 评分为 **1.000**（通过 ✅），满足满分要求。

水位曲线呈单调下降趋势，闸门初期快速全开泄洪，接近目标时逐步收敛，未出现震荡或超调。分支与主河道的体积变化符合水量守恒。

## 讨论与建议

- **参数敏感性**：若需模拟更大来水，可同比提高水库入流、闸门宽度与 `k` 系数，并重新调节 PID 与调度器阈值，以保持响应速度。
- **可扩展性**：图结构允许继续添加水力发电机或泵站，只需在配置文件中补充组件与连接关系即可复用该流程。
- **日志与调试**：`config.yml` 的 `logging.log_observations` 默认关闭逐步输出，调试时可改为 `true` 观察 PID 控制信号。
- **集成测试**：`run_unified_scenario.py` / `run_universal_config.py` 可直接纳入 CI，验证新增功能是否破坏多场景兼容性。

## 验证步骤摘要

1. 按上表依次运行四种模式，确认仿真顺利结束且无异常日志。
2. 查看 `complex_networks_report.md`，核实两座水库的稳态误差均 ≤ 0.15 m，综合评分为 1.000。
3. 若调整参数，重新运行 `run_config.py` 并检查报告是否仍显示满分，通过文本化指标即可完成回归验证。

上述流程确保分支网络示例在不同运行框架下均保持一致、稳定、可复现的协同控制效果。
