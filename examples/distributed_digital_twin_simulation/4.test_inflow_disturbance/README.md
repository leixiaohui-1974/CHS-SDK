# 入流扰动测试系统 - Streamlit应用

这个Streamlit应用为 `4.test_inflow_disturbance.py` 脚本提供了一个直观易用的图形界面，让非技术人员也能轻松进行入流扰动测试和验证。

## 🎯 业务功能

### 核心业务逻辑
- **动态扰动管理**：使用DynamicDisturbanceManager在仿真运行期间持续应用入流变化扰动
- **实时状态监控**：记录入流和水位在整个仿真过程中的变化情况
- **物理核心验证**：验证入流扰动是否成功影响物理计算核心
- **效果可视化分析**：通过图表直观展示扰动效果和系统响应

### 模块依赖
- **core_lib.io.yaml_loader** (SimulationBuilder)：负责加载仿真环境和组件管理
- **core_lib.central_coordination.collaboration.message_bus** (MessageBus)：提供消息总线通信
- **DynamicDisturbanceManager**：动态扰动管理器，负责扰动的注册、激活和应用
- **使用核心库**：完全集成CHS-SDK核心库进行扰动测试

### 数据源
- **仿真环境状态数据**：实时水库状态、组件参数
- **动态扰动管理器状态**：扰动注册、激活、应用状态
- **入流变化数据**：扰动期间的入流量变化记录
- **水位响应数据**：系统对入流变化的响应情况

## 🚀 快速开始

## 📝 关键计算公式

### 入流变化计算
```
扰动后入流 = 基础入流 + 扰动幅值 × 扰动模式函数
阶跃模式：扰动模式函数 = 1 (在扰动期间)
正弦模式：扰动模式函数 = sin(2π × (t - 开始时间) / 持续时间)
```

### 水位变化估算
```
水位变化 ≈ 入流变化 × 时间步长 × 转换系数
转换系数取决于水库表面积和几何形状
```

### 效果验证标准
```
扰动成功：|入流变化| > 0.1 m³/s
扰动失败：|入流变化| ≤ 0.1 m³/s
```

## 📋 关键指标说明

### 扰动参数指标
- **扰动幅值**：入流增加的量，决定扰动强度
- **扰动模式**：扰动的变化规律，影响扰动效果
- **扰动时间**：扰动开始和持续时间，影响累积效应
- **目标组件**：施加扰动的具体组件名称

### 系统响应指标
- **入流变化**：扰动前后入流量的差值
- **水位变化**：扰动前后水位的差值
- **响应时间**：从扰动开始到系统响应的时间
- **稳定时间**：系统达到新稳定状态的时间

### 验证结果指标
- **扰动成功率**：扰动成功影响系统的比例
- **效果显著性**：扰动效果的明显程度
- **系统稳定性**：扰动后系统的稳定程度
- **计算准确性**：扰动后计算结果的准确性

## ⚠️ 使用注意事项

### 参数设置建议
- **扰动幅值**：建议设置为基础入流的10-50%以确保明显效果
- **扰动时间**：建议设置较长的持续时间以观察累积效应
- **时间步长**：建议使用较小的步长以提高计算精度
- **总仿真时间**：应足够长以观察扰动后的系统稳定过程

### 结果解读要点
- **入流变化**：是判断扰动是否成功的主要指标
- **水位变化**：通常比入流变化小，需要高精度观测
- **时间延迟**：系统响应可能存在一定的时间延迟
- **非线性效应**：实际系统可能存在非线性响应特性

### 故障排除指南
- 如果扰动无效果，检查目标组件名称是否正确
- 如果导入失败，确认core_lib环境配置正确
- 如果仿真报错，检查工作目录和配置文件
- 如果效果不明显，尝试增加扰动幅值或延长持续时间

### 性能优化建议
- 使用较大的时间步长可以提高仿真速度
- 减少总仿真时间可以加快测试速度
- 在模拟模式下进行初步测试可以节省时间
- 合理设置扰动参数可以避免不必要的计算
