# 执行器故障扰动测试说明

## 问题描述
该示例验证在层级水库—渠道系统中同时引入延迟、效率下降与完全失灵三类执行器故障时，数字孪生控制架构能否保持水位稳态并完整记录故障发生过程。测试要求在 5–20 s 的窗口内依次激活三种故障，统计各类故障的触发次数与重叠区间，并确保上下游水位在 0.5 mm 容差内波动。

## 建模与情景分析原理
- 使用 `SimulationBuilder` 加载上游水库、三座闸门、两段渠道及下游水库构成的多级输水网络，并保持 1 s 的统一时间步长推进仿真。
- 通过 `DisturbanceConfig` 配置三种执行器故障：闸门延迟故障（5–15 s）、泵效率下降故障（8–18 s）与阀门完全失灵故障（12–20 s），自动推导期望触发次数并写入扰动管理器。
- 在关键时间点抓取组件状态，辅以扰动历史记录，验证多故障同时作用的样本数量，并以 `LEVEL_TOLERANCE=5e-4` 约束上下游水位。

## 结果分析
- 三类故障的触发次数分别达到预期值：延迟故障 11 次、效率下降故障 11 次、完全失灵故障 9 次，说明扰动窗口与时间步长计算准确。
- 故障重叠记录 11 条，覆盖延迟与效率下降的交叠阶段，证实多扰动同时注入的链路完整可追溯。
- 上下游水位的最大偏差均为 0.000 m，远低于 0.0005 m 的性能阈值，控制精度、扰动识别与合理性评分均为 1.0，满足满分要求。

## 讨论与建议
- 现有场景中控制器在长时间故障窗口仍维持稳态，可进一步引入动态设定值或外部扰动，检验控制器在组合工况下的调节余度。
- 建议扩展扰动日志，记录执行器内部状态（如指令排队、效率恢复曲线），便于分析延迟与部分失效对执行机构的具体影响。
- 可在相同框架下引入传感器噪声或通信失步，构建更贴近现场的联动故障场景，为故障诊断策略提供验证基线。
