# 网络扰动测试说明

## 问题描述
示例针对增强消息总线在三类网络扰动（固定延迟、丢包、复合扰动）下的传输可靠性进行评估，关注延迟统计与消息送达率，为多代理协调策略提供通信性能基线。

## 建模原理
- 使用 `EnhancedMessageBus` 与 `NetworkDisturbanceManager` 注入延迟与丢包模型，允许对目标主题与代理精确控制扰动范围。
- 通过 `TestAgent` 统一处理发送与接收逻辑，记录消息时间戳、延迟信息以及投递统计。
- 对组合扰动场景同时激活延迟与高丢包扰动，模拟突发网络退化。
- 统一的伪随机种子确保延迟、抖动与丢包路径稳定复现，便于评估指标与文档数据保持一致。

## 计算结果
- 延迟扰动：种子固定后平均延迟 0.208 s，16 条消息携带延迟标签，全部落在 [0.10 s, 0.30 s] 的容差区间。
- 丢包扰动：50 次发送在两个订阅端共收到 56 条消息，实际丢包率 0.44，符合 [0.25, 0.55] 的预期强度约束。
- 组合扰动：80 轮广播累计 72 条延迟消息，平均延迟 0.087 s、最大延迟 0.152 s，验证延迟曲线与突发丢包阶段均被触发。

## 讨论与建议
- 延迟扰动通过最小 10 条延迟消息和平均延迟容差的断言，保证 QoS 波动被完全复现，可在此基础上进一步构建多级缓冲或自适应调度策略。
- 丢包测试将实际丢包率限制在 0.25–0.55 之间，既验证了扰动注入能力，也为通信协议的冗余设计提供量化指标。
- 组合扰动脚本对延迟覆盖率、平均延迟和峰值延迟均设置下限，确保突发延迟与高丢包阶段真实出现，后续可考虑汇总日志或绘制统计图以降低终端噪声。
